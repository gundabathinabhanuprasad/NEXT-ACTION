## 1. Objective
NextAction has continually recorded task domain mutations throughout Phases 1–14 in the underlying `TaskHistory` model. 

Phase 15 focuses on transforming this audit log foundation into a rich, human-readable, and highly actionable Activity Timeline experience across the entire platform:
- Unify and enrich task history with actor metadata (`actor_name`, `actor_email`, "Former user" fallback, "System" automated fallback) and task title context.
- Provide clear visual timelines in `TaskDetailScreen` with diff cards (`old_value` $\to$ `new_value`), reason callouts, category icons/colors, and category filter chips.
- Provide a dedicated Global Activity Center (`/api/v1/activity` and `ActivityScreen`) with chronological date grouping (Today, Yesterday, Earlier This Week, Earlier This Month), real-time search, action filters, and pagination.
- Integrate dynamic Recent Activity into the `HomeScreen` dashboard and Drawer navigation with "View all" capability.
- Maintain full source traceability for Template (`created_from_template`) and Recurrence (`generated_from_recurrence`) automations from Phase 14.
- Zero mock data; maintain 100% backward compatibility with Phases 1–14; stop at Phase 15.

## 2. Existing History Architecture
An architectural audit of backend and frontend was conducted prior to implementation:
- **Backend**:
  - `TaskHistory` model in `backend/app/models/task_history.py` already contains: `id`, `task_id`, `action`, `old_value`, `new_value`, `reason`, `created_by_user_id`, `created_at`, with foreign keys to `tasks.id` (ondelete CASCADE) and `users.id` (ondelete SET NULL).
  - `TaskService` records mutations across task creation, attempt tracking, override attempts, status changes, priority transitions, assignments/reassignments, postponements, next action scheduling, completion, reopening, and subject line updates.
  - Eager loading (`joinedload`) of `created_by_user` and `task` allows non-destructive data enrichment during serialization without requiring database schema changes or redundant tables.
- **Flutter**:
  - `TaskHistory` model in `lib/models/history/task_history_models.dart`.
  - `TaskDetailScreen` Section 10 was previously a plain list; upgraded into a modern timeline with interactive category filter chips and diff presentation.

## 4. Data Contract
Enriched DTO schema in `backend/app/schemas/history.py`:

```python
class TaskHistoryResponse(BaseModel):
    id: uuid.UUID
    task_id: Optional[uuid.UUID] = None
    task_title: Optional[str] = None
    action: str
    old_value: Optional[str] = None
    new_value: Optional[str] = None
    reason: Optional[str] = None
    created_by_user_id: Optional[uuid.UUID] = None
    actor_name: Optional[str] = None
    actor_email: Optional[str] = None
    created_at: datetime
```

Paginated response wrapper:
```python
class TaskHistoryListResponse(BaseModel):
    items: List[TaskHistoryResponse]
    total: int
    page: int
    page_size: int
```

## 5. Actor Handling & Fallbacks
Actor resolution handles user lifecycle states safely without exposing sensitive data:
1. **Active / Existing User**: `actor_name = user.name`, `actor_email = user.email`.
2. **Deleted User (`created_by_user` is null, `created_by_user_id` is non-null)**: `actor_name = "Former user"`, `actor_email = null`.
3. **Automated / System Operations (`created_by_user_id` is null)**: `actor_name = "System"`, `actor_email = null`.
4. **Security**: Password hashes, tokens, and internal credentials are never included in history payloads.

## 7. Task History API
- **Endpoint**: `GET /api/v1/tasks/{task_id}/history`
- **Supported Query Parameters**:
  - `action`: Filter by exact action name (e.g. `status_changed`, `postponed`).
  - `actor_id`: Filter by actor UUID.
  - `order`: Sort order (`asc` or `desc`, default `asc`).
  - `page`: Page index (1-based, optional).
  - `page_size`: Items per page (1–100, optional).
- **Access Control**: Requires valid JWT bearer token. Nonexistent tasks return 404.

---

## 8. Global Activity API
- **Endpoint**: `GET /api/v1/activity`
- **Supported Query Parameters**:
  - `page`: Page index (default 1).
  - `page_size`: Items per page (default 20, max 100).
  - `action`: Filter by action type.
  - `actor_id`: Filter by actor UUID.
  - `task_id`: Filter by task UUID.
  - `start_date` / `end_date`: Filter by ISO date window.
- **Return Type**: `TaskHistoryListResponse` with eager loaded task titles and user metadata.

## 17. Security
- Unauthenticated requests to `/tasks/{id}/history` and `/activity` are strictly rejected with HTTP 401 Unauthorized.
- Sensitive fields (passwords, JWT secrets, salt hashes) are never exposed.
- Actor identity is derived securely from server JWT token on mutation creation.
- Nonexistent tasks return HTTP 404 Not Found.
